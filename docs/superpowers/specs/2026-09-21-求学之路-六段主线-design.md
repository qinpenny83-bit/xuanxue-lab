# 「求学之路 · 六段主线」设计文档

> 目标：在现有 10 学院 390 节点之上，增加一条「从不懂 → 学到东西 → 运用 → 精通」的纵向主线，让用户随时知道「我在哪一段、还差什么、下一步学什么」。
> 纪律：不新增知识内容、不删除现有功能、全部确定性计算、纯前端零外部依赖。
> 日期：2026-09-21
> 状态：已与用户确认方案（六段主线）、解锁策略（软引导）、奇门/六壬/太乙定位（选修扩展）。

---

## 一、问题与根因

用户反馈：「内容是否充分全面深入？是否需要纵向添加一些，可以让一个小白从不懂到学到东西、再到运用、精通？目前还达不到这个标准。」

盘点结论（390 节点全量统计）：

| 资产 | 数量 | 说明 |
|---|---|---|
| 学院 / 章节 / 节点 | 10 / 65 / 390 | 每个节点 = 一节八段闭环微课程 |
| V3 课程 | 390 节 | lessonFactory 确定性装配 |
| 推理实验 / 易经案例 / 实验室实验 | 80 / 85 / 13 | 全部确定性 |
| 易工坊工作台 / 训练任务 | 6 / 72 | 训练任务每台 12 个 |
| 综合研究院专题 | 4 | L4 解锁 |
| 学徒等级 | L0–L6 | 8 维能力引擎，完全行为驱动 |
| 节点难度等级分布 | L0:22 L1:67 L2:80 L3:70 L4:57 L5:56 L6:29 L7:9 | 已有难度分级 |

根因诊断（纵向缺口）：

1. **学院平级并列**：10 个学院是平级 tabs，小白不知道先学哪个、后学哪个；方法论（本该打底）排在第 3。
2. **节点难度不显现**：节点有 level 0-7，但地图上不区分层级，390 节点像一盘散沙。
3. **学徒等级不被感知**：L0-L6 引擎存在，但地图顶部只显示「X 掌握 · Y 待复习」，不告诉用户正走在哪一段。
4. **没有里程碑与门禁**：阶段升级无测验、无结业、无解锁，精通没有可感知的成就感节点。
5. **易工坊不分阶段**：L0 新手和 L4 高手面对同一批训练任务。

---

## 二、方案总览

「求学之路 · 六段主线」：在现有 390 节点之上叠加一层「组织 + 验证」：

- **六段主线**：把 390 节点按「能力成长」组织成 6 段，每段选定约 12 个核心必修节点，其余为选修（仍全部可自由学习）。
- **阶段结业测验**：每段末尾确定性抽 5 题（从该段核心节点的 apply/counter/masteryCheck 题池抽取），答对 ≥4 题（80%）即本段结业。
- **软引导解锁**：未结业前，后段核心节点显示「建议先完成第 N 段」但不锁死，自由探索不受限。
- **求学之路页面**（新增 1 个轻量页面 `/path`）：六段时间线，显示每段完成度、当前段位、下一个核心节点、结业测验入口。
- **地图改造**：节点卡片标记「★ 必修 / 选修」，地图顶部加当前段位横幅。

## 三、六段主线定义

六段对齐现有学徒等级 L0-L6（L6 出师为最终里程碑），难度跨学院递增：

| 段 | 名称 | 目标等级 | 主题 | 核心节点数 |
|---|---|---|---|---|
| 第 1 段 | 认知启蒙 | L1 | 各体系是什么；事实与解释 | 12 |
| 第 2 段 | 体系基础 | L2 | 阴阳五行干支八卦「字母表」 | 12 |
| 第 3 段 | 结构识别 | L3 | 看懂盘/卦结构，读出基本信息 | 12 |
| 第 4 段 | 规则应用 | L4 | 用规则判断：强弱、爻位、反例 | 12 |
| 第 5 段 | 综合进阶 | L5 | 多变量综合：格局、用神、卦辞、十翼 | 12 |
| 第 6 段 | 独立研究 | L6 | 流派差异、独立分析、出师准备 | 12 |

核心节点选择原则：

1. **跨学院**：每段覆盖方法论 + 至少 2 个主要术数学院（八字/易经为主轴，风水、术数史穿插）。
2. **难度递增**：第 1 段取 level 0-1，第 6 段取 level 4-7，保证平均难度逐段上升。
3. **方法论贯穿**：观察→推理→证据→反例→不确定性的方法论节点，按阶段分布到各段。
4. **奇门/六壬/太乙**：仅「是什么」节点进第 1 段，「边界与学习路径」节点进第 6 段，其余作为选修扩展。
5. **民俗/神秘文化**：作为文化选修，不进核心必修。

## 五、UI 层设计

### 1. 求学之路页面 `/path`（新建轻量页面 `src/pages/Path.jsx`）

- **顶部横幅**：当前学徒等级（L0-L6 徽章 + 名称 + 描述）+ 核心必修进度（已完成 X/72）。
- **六段时间线**：纵向 6 张段卡片，每张显示：
  - 段名 + 目标等级 + emoji + 完成度条（done/total）
  - 结业状态：未开始 / 学习中 / 已结业（🏆）
  - 展开后列出核心节点（✓ 已完成 / ○ 开始 / 🔒 建议先完成前段），点击直达课程
  - 「阶段测验」按钮：当前段可进入测验，前段未结业显示「建议先完成第 N 段」软提示
- **下一个核心节点**：页面顶部固定推荐「下一个该学的核心节点」（当前段第一个未完成的必修节点），一键跳转。

### 2. 阶段测验交互（`Path.jsx` 内嵌）

- 一次 5 题，逐题作答，答后立即显示 feedback 与正确答案（复用节点 explain）。
- 全部答完显示得分与是否结业（≥4/5 通过），通过后写 `RECORD_PATH_QUIZ`。
- 未通过显示「还差 X 题，回去复习这几节课」并列出错题对应节点，可一键跳回。

### 3. 学习地图改造（`Map.jsx`）

- 节点卡片：核心节点显示「★ 必修」（indigo 标记），选修显示「选修」（灰色小标）。
- 地图顶部状态行：追加当前段位信息「🌱 第 2 段·体系基础 5/12」+「求学之路 →」按钮。
- 顶部导航（`Layout.jsx`）：新增「求学之路」入口，与「地图 / 易工坊 / 成长」对齐。

### 4. 路由

- `App.jsx` 新增 `case 'path': return <PathPage />`。

## 六、Agent 联动

- `localAgentEngine` 的推荐在「没有更紧急的复习/补强任务」时，优先推荐「当前段的第一个未完成核心必修节点」（调 `pathEngine.nextCoreNode`）。
- 推荐理由可引用段位信息：「完成第 N 段·XX 的核心必修节点」。此联动为增强，不改变现有优先级。

## 七、测试设计（`tests/r7-path.test.js`）

| 用例 | 断言 |
|---|---|
| 六段结构完整 | `PATH_STAGES.length === 6`，每段 `coreNodeIds.length >= 8` |
| 核心节点全部有效 | 每个 coreNodeId 都能在 `CURRICULUM_NODES` 中找到 |
| 核心节点无重复 | `ALL_CORE_IDS` 去重后长度不变 |
| 难度逐段上升 | 第 n+1 段核心节点平均 level >= 第 n 段平均 level |
| 学院覆盖 | 六段核心节点至少覆盖 6 个学院（方法论、八字、易经必在） |
| 阶段测验确定性 | 同一 stage 两次 `stageQuiz()` 返回完全相同的题 |
| 结业判定 | 答对 4/5 → passed=true；答对 3/5 → passed=false |
| 进度计算 | 构造 state：部分节点 mastery=4 → done 数正确 |
| 软引导 | 未结业不影响节点可访问性（无硬锁字段） |
| 持久化 | `RECORD_PATH_QUIZ` 后 `state.pathQuizzes` 正确更新 |

## 八、验收标准

1. `/path` 页面可访问，六段时间线完整展示，当前段位正确（与学徒等级一致）。
2. 完成第 1 段全部核心节点后，阶段测验可进入；答对 4/5 结业，进入第 2 段。
3. 地图上核心节点显示「★ 必修」，顶部显示当前段位横幅。
4. 未结业时后段节点可点击（软引导，不硬锁）。
5. 全量回归测试通过（原 1277 + 新增 r7 用例）。
6. 生产构建成功，应用地址保持 `http://localhost:5178/`。

## 九、不做的事（YAGNI）

- 不新增知识节点、不修改任何现有节点数据内容。
- 不做硬解锁、不做时间限制、不做每日任务。
- 不引入第三方依赖、不接 LLM / 外部 API。
- 不改动案例/实验/易工坊现有逻辑（易工坊分阶段开放留待后续迭代）。
